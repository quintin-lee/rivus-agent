# timed_out 状态修正 Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让真实超时的 run 落终态 `timed_out` + 发 `run.timed_out` 事件，而不是被误标为 `verification_failed`/`model_failed`；前端把 `run.timed_out` 纳入终态/刷新集，运行气泡显示橙色 "Run timed out"。

**Architecture:** 后端在 `runtime.go` 的 `run()` 事件循环结束、`waitApproval` 判定之后、`modelFailed` 判定之前，插入一个 `errors.Is(ctx.Err(), context.DeadlineExceeded)` 分支。**关键**：此刻 ctx 已过期，`database/sql` 会对它短路所有写（prepareContext 先返回 `ctx.Err()` 不落库），所以本分支的 `UpdateStatus`/事件 `Append`/清 checkpoint **必须**用 `context.Background()`，否则整个修复静默 no-op。前端 5 处各加 1 行 + `AssistantBubble` 橙色分支。

**Tech Stack:** Go（`backend/`，集成测试 `backend/tests/integration/` + `testutil.Harness`）；React/Vite/Zustand（`frontend/`，`npx tsc --noEmit` + `npx vitest run`）。

**Spec:** `docs/superpowers/specs/2026-10-15-timed-out-design.md`

**Out of scope（明确不做）:** `budget.go` 的 `CheckIteration`/`ErrTimeout` 死代码清理；`runner_eino.go` drain 的 `EvtRunCancelled` 发射（保留，由 `run()` 层区分 cancel vs timeout）。

新建 `backend/tests/integration/runtime_timed_out_test.go`（`package integration`，与既有集成测试同包）。harness API 实测（`tests/testutil/harness.go`）：`testutil.New(t)` 给 `*testutil.Harness`；`CreateRun(session, payload, idem)` 的 `payload` 带 `budget`（键 `max_duration_seconds`）；`WaitTerminal(id, timeout)` 返回 `domain.Run`；`h.Events.ListAfter(ctx, runID, 0, limit)` 返回 `[]domain.AgentEvent`（字段 `.Type`）；`Model.EnqueueFunc(fn)` 阻塞模型；仓库用 plain `t.Fatal`（非 testify）。

```go
package integration

import (
	"context"
	"testing"
	"time"

	"github.com/cloudwego/eino/schema"

	"rivus-agent-backend/internal/domain"
	"rivus-agent-backend/tests/testutil"
)

func TestRunTimedOut(t *testing.T) {
	h := testutil.New(t)
	// 模型阻塞 2s，越过 1s 的 run deadline
	h.Model.EnqueueFunc(func(_ int, _ []*schema.Message) (*schema.Message, error) {
		time.Sleep(2 * time.Second)
		return &schema.Message{Role: schema.User, Content: "never reached"}, nil
	})
	ses := h.CreateSession("s")
	id, code, _ := h.CreateRun(ses, map[string]any{
		"goal":   "block until timeout",
		"budget": map[string]any{"max_duration_seconds": 1}, // < harness 120 上限，clamp 保留 1
	}, "timeout-1")
	if code != 201 {
		t.Fatalf("create run: %d", code)
	}
	run := h.WaitTerminal(id, 15*time.Second)
	if run.Status != domain.RunTimedOut {
		t.Fatalf("want timed_out, got %s (%s)", run.Status, run.ErrorSummary)
	}
	if run.ErrorCode != "timed_out" {
		t.Fatalf("want error_code timed_out, got %q", run.ErrorCode)
	}
	evs, err := h.Events.ListAfter(context.Background(), id, 0, 1000)
	if err != nil {
		t.Fatalf("list events: %v", err)
	}
	for _, e := range evs {
		if e.Type == domain.EvtRunTimedOut {
			return // run.timed_out 已落库（经 context.Background() 写）
		}
	}
	t.Fatalf("run.timed_out event not persisted")
}
```

```go
	if errors.Is(ctx.Err(), context.DeadlineExceeded) {
		// ctx 此刻已过期：database/sql 会对它短路写操作（prepareContext 先
		// 返回 ctx.Err()，不落库）。故本分支所有写库走 context.Background()，
		// 否则 UpdateStatus/事件 Append 静默失败、run 永远停在 running。
		bgCtx := context.Background()
		_ = r.deps.Tasks.UpdateStatus(bgCtx, ownerID, run.ID, domain.RunTimedOut, "timed_out", "run exceeded max duration budget")
		r.append(bgCtx, run.ID, domain.EvtRunTimedOut, "run timed out")
		observability.IncrRunFinished(false)
		r.deps.Runner.DeleteCheckpointsByRun(bgCtx, run.ID)
		return
	}
```
